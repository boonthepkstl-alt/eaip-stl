# การอนุมัติงานจาก Supervisor

## บทนำ

เอกสารนี้ต่อยอดจาก [[20260815-01-task-creation-assignment]] ซึ่งครอบคลุมการสร้างงานใหม่และมอบหมายงานโดย Staff แต่ระบุไว้อย่างชัดเจนว่า **ไม่ครอบคลุม** เรื่องการอนุมัติงานจากหัวหน้าทีม/Supervisor เอกสารฉบับนี้จึงกำหนดความต้องการสำหรับขั้นตอนที่ **Supervisor** ต้องตรวจสอบและอนุมัติงานที่ Staff สร้าง+มอบหมายแล้ว ก่อนที่งานจะเริ่มเข้าสู่การดำเนินการจริง

## ขอบเขต

- ครอบคลุมขั้นตอนการอนุมัติงานที่เกิดขึ้น **หลังจาก** Staff สร้างงาน (FR-01) และมอบหมายงานให้สมาชิกในทีม/โครงการเดียวกัน (FR-02) หรือมอบหมายให้ตนเอง (FR-03) เสร็จสิ้นแล้ว โดยงานจะเข้าสู่สถานะ "รออนุมัติ" ก่อนเริ่มดำเนินการจริง
- Supervisor หมายถึงผู้ใช้ที่มีบทบาท (role) ระดับ **Project-level** ที่มีสิทธิ์กำกับดูแลทีม/โครงการเดียวกับงานนั้น (ตามรูปแบบสิทธิ์ 2 ระดับของระบบ คือ System-level และ Project-level แบบ union ของหลายบทบาท) ไม่ใช่ System-level
- ครอบคลุมทั้งกรณี Supervisor **อนุมัติ (Approve)** และ **ปฏิเสธ (Reject)** พร้อมเหตุผลประกอบ
- ครอบคลุมกรณี Staff แก้ไขงานที่ถูกปฏิเสธแล้วส่งขออนุมัติใหม่
- ไม่ครอบคลุม: การอนุมัติหลายลำดับชั้น (multi-level approval), การมอบอำนาจอนุมัติ (delegate), การอนุมัติ Sub Task แยกจาก Parent Task, การอนุมัติการเปลี่ยนสถานะอื่นๆ ภายหลังเริ่มงาน (เช่น การอนุมัติปิดงาน/เสร็จสิ้นงาน) — ประเด็นเหล่านี้ให้พิจารณาเป็น requirement แยกในอนาคต
- เหตุผลการอนุมัติ/ปฏิเสธ จัดเก็บเป็น Rich Text/comment ที่ผูกกับ Task ในฐานข้อมูล ตามรูปแบบเดียวกับ Task detail/comment (แยกจาก Project Doc/Wiki ที่เป็น Markdown ผูก Git)
- ยังไม่ผูก tech stack หรือรายละเอียดการ implement ใดๆ ให้เป็นไปตาม `technology-stack.md` เมื่อมีการตัดสินใจจริง

## Functional Requirements (FR)

| รหัส | ความต้องการ | รายละเอียด | ระดับความสำคัญ |
|------|--------------|-------------|------------------|
| FR-04 | ตั้งสถานะ "รออนุมัติ" หลังมอบหมายงาน | เมื่อ Staff มอบหมายงานสำเร็จ (ตาม FR-02 หรือ FR-03) ระบบต้องเปลี่ยนสถานะงานเป็น "รออนุมัติ" โดยอัตโนมัติ และแจ้งเตือน Supervisor ของทีม/โครงการนั้นทันที ก่อนที่งานจะเข้าสู่สถานะดำเนินการปกติ | สูง |
| FR-05 | Supervisor อนุมัติงาน | Supervisor ที่มีสิทธิ์ระดับ Project-level ในทีม/โครงการเดียวกับงานสามารถอนุมัติงานที่อยู่ในสถานะ "รออนุมัติ" ได้ เมื่ออนุมัติแล้ว ระบบเปลี่ยนสถานะงานเป็นสถานะเริ่มดำเนินการ (เช่น "รอดำเนินการ" ตาม FR-01) และแจ้งเตือนผู้ถูกมอบหมาย | สูง |
| FR-06 | Supervisor ปฏิเสธงานพร้อมเหตุผล | Supervisor สามารถปฏิเสธงานที่อยู่ในสถานะ "รออนุมัติ" ได้ โดยต้องระบุเหตุผลการปฏิเสธ (บันทึกเป็น Rich Text/comment ผูกกับ Task) ระบบเปลี่ยนสถานะงานเป็น "ถูกปฏิเสธ" และแจ้งเตือน Staff ผู้สร้างงานและผู้ถูกมอบหมายให้ทราบ | สูง |
| FR-07 | แก้ไขและขออนุมัติใหม่หลังถูกปฏิเสธ | Staff ผู้สร้างงานสามารถแก้ไขรายละเอียดงานที่ถูกปฏิเสธ แล้วส่งขออนุมัติใหม่ได้ ระบบเปลี่ยนสถานะงานกลับเป็น "รออนุมัติ" อีกครั้งเมื่อส่งใหม่ และแจ้งเตือน Supervisor อีกครั้ง | กลาง |

## Non-Functional Requirements (NFR)

| รหัส | ด้าน | ความต้องการ |
|------|------|--------------|
| NFR-02 | ความปลอดภัย/สิทธิ์การใช้งาน (Authorization) | เฉพาะผู้ใช้ที่มีบทบาท Supervisor ระดับ Project-level ในทีม/โครงการเดียวกับงานเท่านั้นที่มีสิทธิ์อนุมัติ (FR-05) หรือปฏิเสธ (FR-06) งานนั้น ระบบต้องปฏิเสธคำขออนุมัติ/ปฏิเสธจากผู้ใช้ที่ไม่มีสิทธิ์ในทุกช่องทางที่เรียกใช้งาน |
