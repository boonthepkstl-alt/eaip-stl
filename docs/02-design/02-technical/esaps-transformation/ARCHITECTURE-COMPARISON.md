# Architecture Comparison — ESAPS vs. Company Standards

อ้างอิงจาก [[INDEX|INDEX.md]]. เทียบ 4 แหล่ง: `esaps` (โค้ดจริงที่ root ของ repo นี้), `template/react-template-main`, `template/go-template-main`, `starter-kit` (`.claude/agents`+`.claude/skills` ในโปรเจกต์นี้)

| Area | ESAPS (root) | react-template-main | go-template-main | starter-kit | Decision |
|---|---|---|---|---|---|
| Frontend framework | React 19 + Vite 6, ไม่มี router (state-based nav ใน `App.tsx`) | React 18 + Vite 5 + React Router 6 | — | — | **Migrate**: ย้ายไป React Router ตาม template, คง React 19 ไว้ได้ (CLAUDE.md อนุญาตปรับ version ใหม่กว่าได้) |
| State management | `useState` ในระดับ `App.tsx` (page, assetId, ticketId, employeeId, licenseId) | Zustand + Context API (Auth/Theme) | — | — | **Refactor**: ย้าย auth/global state ไป Context ตาม template, ที่เหลือใช้ local state/Zustand ตามความจำเป็น |
| API client | ไม่มี — หน้าจออ่านจาก `src/data/*.ts` (mock) โดยตรง, มี `fetch` ตรงไปยัง `/api/ai/*` เฉพาะจุด | `src/services/*.ts` + Axios interceptor (auto-inject token, 401 redirect) | REST ผ่าน Fiber controller/service/repository | — | **New**: สร้าง service layer ตาม template ทั้งหมด, เลิกอ่าน mock data ตรงจากหน้าจอ |
| Component library | มี UI kit ครบ (`src/components/ui/*`: Button, Card, Modal, Drawer, Toast, Tabs, Pagination ฯลฯ) + `AppShell` layout | ไม่มี UI kit สำเร็จรูป (เตรียมโครง component/pages เปล่า) | — | — | **Keep**: นี่คือจุดแข็งที่สุดของ ESAPS — ย้าย UI kit + AppShell เข้า template โดยไม่ต้องสร้างใหม่ |
| Backend framework | Express 4 ไฟล์เดียว (`server.ts`) ผสม Vite dev middleware + Gemini client + business logic | — | Go + Fiber, layered controller→service→repository→model | — | **Replace**: ย้าย backend ทั้งหมดไป Go/Fiber ตาม `go-template-main` (มาตรฐานบังคับจาก CIO ใน `docs/02-design/02-technical/technology-stack.md`) |
| Backend structure | ไม่มีการแบ่ง layer — routes/AI client/fallback logic รวมกันใน `server.ts` เดียว | — | `controller/`, `service/`, `repository/`, `model/`, `middleware/`, `handler/`, `util/`, `logger/` | — | **Replace**: ใช้โครง layer ของ go-template ทั้งหมด, map endpoint AI ปัจจุบันเป็น controller/service ใหม่ |
| Authentication | Placeholder — `Login`/`ForgotPassword`/`Register` เป็น UI เท่านั้น, profile "Alex Morgan / Administrator" hardcode ใน `AppShell`, sign-out คือ navigate ไป `login` ไม่มี token จริง | JWT + Context (`AuthContext`) + Axios interceptor + `ProtectedRoute` | JWT (`Authorization: Bearer` หรือ cookie `stl_token`) + `RequireRole()` middleware + token blacklist สำหรับ logout | — | **Replace**: ต่อ frontend เข้ากับ JWT flow จริงของ go-template, ปิด placeholder auth ทั้งหมด — ดู [[AUTH-RBAC|AUTH-RBAC.md]] |
| Database | ไม่มี — ทุกอย่างเป็น mock data ใน `src/data/*.ts`; มี `@supabase/supabase-js` เป็น dependency แต่ไม่พบการใช้งานจริงในโค้ดที่ตรวจ | — | `DBManager` รองรับหลาย engine พร้อมกัน (PostgreSQL master+read-replica, Oracle, MSSQL, Tarantool) แบบ hot-reload config, มี `sql/{pg,oracle,mssql,tt}/` migration ต่อ engine | — | **New**: ต้องสร้าง schema จริงบน PostgreSQL ตาม `go-template-main` — ดู [[DATABASE-DESIGN|DATABASE-DESIGN.md]] |

| Error handling | try/catch ในแต่ละ endpoint ของ `server.ts`, ไม่มี error boundary ฝั่ง React | `ErrorBoundary` component | try/catch ต่อ controller คืน `fiber.Map{"message","error"}` เป็นมาตรฐาน | — | **Migrate**: เพิ่ม `ErrorBoundary` ฝั่ง frontend, ใช้ pattern error response ของ go-template ฝั่ง backend |
| Config/secrets | `.env` (`GEMINI_API_KEY` เท่านั้น), เก็บ key ไว้ที่ server (ไม่หลุดไป frontend — ถูกต้องแล้ว) | `.env`/`.env.production`, `VITE_API_URL` | Viper + `app.env`, รองรับ Infisical (`util/infisicalUtils.go`) สำหรับ secret management จริง | — | **New**: ต้องเพิ่ม config สำหรับ DB/Auth/Storage/Integration ที่ยังไม่มีเลยตอนนี้ |
| Testing | ไม่มี test ผูกไว้ใน `package.json` เลย | ไม่ระบุ test runner ชัดเจนใน template (มี ESLint/Prettier) | มี `*_test.go` ตัวอย่าง + `go test -coverprofile` ใน README, มี sonar config | — | **New**: ต้องสร้าง test suite ทั้งฝั่ง frontend/backend/AI ตั้งแต่ต้น — ดู [[TEST-STRATEGY|TEST-STRATEGY.md]] |
| DevOps/Docker | ไม่มี Dockerfile ที่ root | มี `Dockerfile`, `.dockerignore`, ตัวอย่าง `docker-compose.yml` ใน `SETUP.md` | ไม่พบ Dockerfile ในไฟล์ที่ตรวจ (มีแต่ sonar config) — ต้องตรวจเพิ่มถ้าจะใช้จริง | — | **New**: นำ Docker ของ react-template มาใช้ฝั่ง frontend, ต้องสร้าง Dockerfile ของ backend เพิ่มเองเพราะ go-template ไม่มีให้ |
| Observability | ไม่มี | ไม่มี | OpenTelemetry/Jaeger พร้อม env toggle (`OTEL_ENABLED`) | — | **Migrate**: ใช้ของ go-template ทั้งหมด, ไม่ต้องสร้างใหม่ |

## สรุปตาม category (KEEP / MIGRATE / REFACTOR / REPLACE / REMOVE / NEW)

- **KEEP**: UI kit ทั้งหมดใน `src/components/ui/`, `AppShell`, การจัด layout/navigation label ของทุกโมดูล, แนวคิด fallback engine ของ AI, การไม่ส่ง `GEMINI_API_KEY` ให้ frontend เห็น
- **MIGRATE**: 4 AI endpoint (ย้าย implementation จาก Express เป็น Go), OpenTelemetry tracing ของ go-template, error-response convention ของ go-template
- **REFACTOR**: state-based routing → React Router, ข้อมูลใน `src/data/*.ts` → เรียกผ่าน API service layer, `server.ts` ไฟล์เดียว → แยก controller/service/repository
- **REPLACE**: Express backend → Go/Fiber backend, placeholder auth → JWT+RBAC จริงของ go-template
- **REMOVE**: mock data ที่ hardcode ใน production code path (ย้ายไปเป็น test fixture/seed แทนการลบทิ้งเฉยๆ), ชื่อ package `react-example` ที่ยังไม่เปลี่ยน
- **NEW**: database schema จริงทั้งหมด (ไม่มีอยู่เลยตอนนี้), authentication backend จริง, RBAC ที่บังคับจริงทั้ง frontend/backend, test suite ทั้งหมด, CI/CD, AI data-grounding layer
