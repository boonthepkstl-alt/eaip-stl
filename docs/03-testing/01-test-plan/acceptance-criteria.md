# Acceptance Criteria

เอกสารนี้กำหนดเกณฑ์ยอมรับ (Acceptance Criteria) แบบ Given-When-Then ต่อทุกรหัส FR/NFR ใน
[[backlog]] จัดกลุ่มตามหัวข้อฟีเจอร์เดียวกับ [[feature-list]] (ลำดับ/ชื่อหัวข้อตรงกันเพื่อให้ไล่อ่าน
คู่กันได้ง่าย) อ้างอิงรายละเอียดพฤติกรรมจริงจากเอกสาร spec ต้นทาง:
[[20260815-01-task-creation-assignment]] และ [[20260815-02-supervisor-task-approval]]

ระดับความสำคัญ (สูง/กลาง/ต่ำ) ที่กำกับต่อท้ายรหัสแต่ละหัวข้อ ดึงมาจาก [[backlog]] โดยตรงเสมอ

## 1. สร้างงานใหม่และมอบหมายงานให้ทีม

อ้างอิง: [[feature-list#1. สร้างงานใหม่และมอบหมายงานให้ทีม|feature-list #1]],
[[user-journey#Journey: Staff สร้างงานใหม่และมอบหมายงานให้ทีม|user-journey]]

#### FR-01 (สูง) — [[20260815-01-task-creation-assignment#Functional Requirements (FR)|สร้างงานใหม่]]

**AC-1 (Happy path — สร้างงานสำเร็จ):**
- **Given** Staff ล็อกอินอยู่และเปิดหน้าสร้างงานใหม่
- **When** Staff กรอกครบทุกฟิลด์ที่จำเป็น (ชื่องาน, รายละเอียด (Rich Text), ผู้รับมอบหมาย, กำหนดส่ง,
  ระดับความสำคัญ) แล้วกดบันทึก
- **Then** ระบบสร้างงานสำเร็จ กำหนดสถานะเริ่มต้นให้อัตโนมัติ และดำเนินการต่อยอดตาม FR-04
  (เปลี่ยนสถานะเป็น "รออนุมัติ" ทันที เนื่องจากการสร้างงานผูกกับการมอบหมายงานเสมอ)

**AC-2 (Negative — ฟิลด์จำเป็นขาดหาย):**
- **Given** Staff เปิดหน้าสร้างงานใหม่
- **When** Staff กรอกไม่ครบทุกฟิลด์ที่จำเป็น (เช่น ไม่ระบุกำหนดส่ง หรือไม่ระบุระดับความสำคัญ) แล้วกด
  บันทึก
- **Then** ระบบปฏิเสธคำขอ ไม่สร้างงาน และแจ้งให้ Staff ทราบว่าฟิลด์ใดยังขาดหาย

**AC-3 (Negative — รูปแบบข้อมูลไม่ถูกต้อง):**
- **Given** Staff กรอกฟิลด์ครบทุกช่อง
- **When** ฟิลด์ใดฟิลด์หนึ่งมีรูปแบบไม่ถูกต้อง (เช่น กำหนดส่งไม่ใช่วันที่ที่ถูกต้อง)
- **Then** ระบบปฏิเสธคำขอ ไม่สร้างงาน และแจ้งข้อผิดพลาดของรูปแบบข้อมูล

#### FR-02 (สูง) — [[20260815-01-task-creation-assignment#Functional Requirements (FR)|มอบหมายงานภายในทีม/โครงการเดียวกัน]]

**AC-1 (Happy path — มอบหมายให้สมาชิกในทีม/โครงการเดียวกัน):**
- **Given** Staff สร้างงานใหม่และเลือกผู้รับมอบหมายเป็นสมาชิกอื่นในทีม/โครงการเดียวกันกับตน
- **When** Staff บันทึกการมอบหมาย
- **Then** ระบบตรวจสอบว่าผู้รับมอบหมายเป็นสมาชิกของทีม/โครงการเดียวกันก่อน แล้วบันทึกการมอบหมายสำเร็จ

**AC-2 (Negative — มอบหมายข้ามทีม/โครงการ):**
- **Given** Staff สร้างงานใหม่และเลือกผู้รับมอบหมายที่ไม่ได้อยู่ในทีม/โครงการเดียวกันกับตน
- **When** Staff บันทึกการมอบหมาย
- **Then** ระบบปฏิเสธคำขอมอบหมายงานทั้งหมด ไม่บันทึกงาน (สอดคล้องกับ NFR-01)

#### FR-03 (สูง) — [[20260815-01-task-creation-assignment#Functional Requirements (FR)|มอบหมายงานให้ตนเอง (Self-assign)]]

**AC-1 (Happy path — self-assign):**
- **Given** Staff สร้างงานใหม่
- **When** Staff เลือกผู้รับมอบหมายเป็นตนเอง
- **Then** ระบบอนุญาตให้มอบหมายงานให้ตนเองได้ทันที โดยไม่ต้องตรวจสอบ scope ทีม/โครงการเพิ่มเติม
  และไม่ถือเป็นข้อผิดพลาดหรือถูกจำกัดสิทธิ์

#### NFR-01 (สูง) — [[20260815-01-task-creation-assignment#Non-Functional Requirements (NFR)|ความปลอดภัย/สิทธิ์การใช้งาน (Authorization) ในการมอบหมายงาน]]

**AC-1 (บังคับใช้กฎ FR-02 ทุกช่องทาง):**
- **Given** ผู้ใช้พยายามมอบหมายงานให้ผู้ที่ไม่ได้อยู่ในทีม/โครงการเดียวกัน ไม่ว่าจะเรียกผ่านช่องทางใด
  ของระบบ (เช่น หน้าเว็บ หรือเรียก operation ตรง)
- **When** ระบบประมวลผลคำขอมอบหมายงานนั้น
- **Then** ระบบต้องปฏิเสธคำขอทุกกรณีโดยไม่มีข้อยกเว้น (การตรวจสอบเกิดที่ Service layer เสมอ ไม่ใช่
  แค่ระดับ UI/Client)

## 2. อนุมัติ/ปฏิเสธงานโดย Supervisor

อ้างอิง: [[feature-list#2. อนุมัติ/ปฏิเสธงานโดย Supervisor|feature-list #2]],
[[user-journey#Journey: Supervisor ตรวจสอบและอนุมัติ/ปฏิเสธงาน|user-journey]]

#### FR-04 (สูง) — [[20260815-02-supervisor-task-approval#Functional Requirements (FR)|ตั้งสถานะ "รออนุมัติ" หลังมอบหมายงาน]]

**AC-1 (Happy path — ตั้งสถานะและแจ้งเตือนอัตโนมัติ):**
- **Given** Staff มอบหมายงานสำเร็จ (ตาม FR-02 หรือ FR-03)
- **When** ระบบบันทึกการมอบหมายเสร็จสิ้น
- **Then** ระบบเปลี่ยนสถานะงานเป็น "รออนุมัติ" โดยอัตโนมัติทันที และสร้าง/ส่ง Notification ให้
  Supervisor ทุกคนของทีม/โครงการนั้นทันที

#### FR-05 (สูง) — [[20260815-02-supervisor-task-approval#Functional Requirements (FR)|Supervisor อนุมัติงาน]]

**AC-1 (Happy path — อนุมัติงานที่รออนุมัติ):**
- **Given** งานอยู่ในสถานะ "รออนุมัติ" และผู้เรียกเป็น Supervisor ที่มีสิทธิ์ระดับ Project-level ใน
  ทีม/โครงการเดียวกับงานนั้น
- **When** Supervisor กดอนุมัติงาน
- **Then** ระบบเปลี่ยนสถานะงานเป็นสถานะเริ่มดำเนินการ (เช่น "รอดำเนินการ"), บันทึก
  TaskStatusHistory และแจ้งเตือนผู้ถูกมอบหมายทันที

**AC-2 (Negative — งานไม่ได้อยู่ในสถานะ "รออนุมัติ"):**
- **Given** งานมีสถานะปัจจุบันไม่ใช่ "รออนุมัติ" (เช่น อนุมัติไปแล้ว หรือถูกปฏิเสธไปแล้ว)
- **When** Supervisor พยายามกดอนุมัติงานนั้นซ้ำ
- **Then** ระบบปฏิเสธคำขอ พร้อมแจ้งสถานะปัจจุบันของงานให้ทราบ

**AC-3 (Negative — ไม่พบงาน):**
- **Given** รหัสงาน (Task id) ที่ระบุไม่มีอยู่ในระบบ
- **When** Supervisor พยายามอนุมัติงานด้วยรหัสนั้น
- **Then** ระบบแจ้งว่าไม่พบข้อมูลงาน

#### FR-06 (สูง) — [[20260815-02-supervisor-task-approval#Functional Requirements (FR)|Supervisor ปฏิเสธงานพร้อมเหตุผล]]

**AC-1 (Happy path — ปฏิเสธงานพร้อมเหตุผล):**
- **Given** งานอยู่ในสถานะ "รออนุมัติ" และผู้เรียกเป็น Supervisor ที่มีสิทธิ์ระดับ Project-level ใน
  ทีม/โครงการเดียวกับงานนั้น
- **When** Supervisor กรอกเหตุผลการปฏิเสธ (Rich Text) แล้วกดปฏิเสธงาน
- **Then** ระบบบันทึกเหตุผลเป็น TaskComment ผูกกับ Task, เปลี่ยนสถานะงานเป็น "ถูกปฏิเสธ", บันทึก
  TaskStatusHistory และแจ้งเตือน Staff ผู้สร้างงานและผู้ถูกมอบหมายทันที

**AC-2 (Negative — ไม่ระบุเหตุผลการปฏิเสธ):**
- **Given** งานอยู่ในสถานะ "รออนุมัติ" และ Supervisor มีสิทธิ์ถูกต้อง
- **When** Supervisor กดปฏิเสธงานโดยไม่กรอกเหตุผล
- **Then** ระบบปฏิเสธคำขอ (ไม่เปลี่ยนสถานะงาน) และแจ้งว่าต้องระบุเหตุผลการปฏิเสธเสมอ

**AC-3 (Negative — งานไม่ได้อยู่ในสถานะ "รออนุมัติ"):**
- **Given** งานมีสถานะปัจจุบันไม่ใช่ "รออนุมัติ"
- **When** Supervisor พยายามปฏิเสธงานนั้น
- **Then** ระบบปฏิเสธคำขอ พร้อมแจ้งสถานะปัจจุบันของงานให้ทราบ

#### NFR-02 (สูง) — [[20260815-02-supervisor-task-approval#Non-Functional Requirements (NFR)|ความปลอดภัย/สิทธิ์การใช้งาน (Authorization) ในการอนุมัติ/ปฏิเสธงาน]]

**AC-1 (Negative — ผู้ใช้ไม่มีสิทธิ์ Supervisor ในทีม/โครงการเดียวกัน):**
- **Given** ผู้ใช้ไม่มีบทบาท Supervisor ระดับ Project-level ในทีม/โครงการเดียวกับงานนั้น (ไม่ว่าจะ
  เป็น Staff ธรรมดา หรือ Supervisor ของทีม/โครงการอื่น)
- **When** ผู้ใช้พยายามอนุมัติหรือปฏิเสธงานนั้น ไม่ว่าจะเรียกผ่านช่องทางใดของระบบ
- **Then** ระบบต้องปฏิเสธคำขอทุกกรณีโดยไม่มีข้อยกเว้น (การตรวจสอบเกิดที่ Service layer เสมอ)

## 3. แก้ไขงานที่ถูกปฏิเสธและขออนุมัติใหม่

อ้างอิง: [[feature-list#3. แก้ไขงานที่ถูกปฏิเสธและขออนุมัติใหม่|feature-list #3]],
[[user-journey#Journey: Supervisor ตรวจสอบและอนุมัติ/ปฏิเสธงาน|user-journey]]

#### FR-07 (กลาง) — [[20260815-02-supervisor-task-approval#Functional Requirements (FR)|แก้ไขและขออนุมัติใหม่หลังถูกปฏิเสธ]]

**AC-1 (Happy path — แก้ไขและส่งขออนุมัติใหม่):**
- **Given** งานอยู่ในสถานะ "ถูกปฏิเสธ" และผู้เรียกเป็นผู้สร้างงานเดิมของงานนั้น
- **When** Staff แก้ไขฟิลด์อย่างน้อยหนึ่งฟิลด์ (ชื่องาน, รายละเอียด, ผู้รับมอบหมาย, กำหนดส่ง, ระดับ
  ความสำคัญ) แล้วส่งขออนุมัติใหม่
- **Then** ระบบเปลี่ยนสถานะงานกลับเป็น "รออนุมัติ" ทันที บันทึก TaskStatusHistory และแจ้งเตือน
  Supervisor ของทีม/โครงการนั้นอีกครั้ง

**AC-2 (Negative — ผู้เรียกไม่ใช่ผู้สร้างงานเดิม):**
- **Given** งานอยู่ในสถานะ "ถูกปฏิเสธ"
- **When** ผู้ใช้ที่ไม่ใช่ผู้สร้างงานเดิม (เช่น ผู้ถูกมอบหมายที่ไม่ใช่ผู้สร้าง) พยายามแก้ไขและส่งขอ
  อนุมัติใหม่
- **Then** ระบบปฏิเสธคำขอ

**AC-3 (Negative — งานไม่ได้อยู่ในสถานะ "ถูกปฏิเสธ"):**
- **Given** งานมีสถานะปัจจุบันไม่ใช่ "ถูกปฏิเสธ" (เช่น ยังรออนุมัติอยู่ หรืออนุมัติไปแล้ว)
- **When** Staff ผู้สร้างงานพยายามแก้ไขและส่งขออนุมัติใหม่
- **Then** ระบบปฏิเสธคำขอ พร้อมแจ้งสถานะปัจจุบันของงานให้ทราบ

**AC-4 (Negative — เปลี่ยนผู้รับมอบหมายเป็นผู้ที่ไม่ได้อยู่ในทีม/โครงการเดียวกัน):**
- **Given** งานอยู่ในสถานะ "ถูกปฏิเสธ" และผู้เรียกเป็นผู้สร้างงานเดิม
- **When** Staff แก้ไขผู้รับมอบหมายเป็นผู้ที่ไม่ได้อยู่ในทีม/โครงการเดียวกันกับงาน แล้วส่งขออนุมัติใหม่
- **Then** ระบบปฏิเสธคำขอทั้งหมด ไม่เปลี่ยนสถานะงาน (สอดคล้องกับ NFR-01 ที่ใช้กฎเดียวกับการมอบหมาย
  งานครั้งแรก)
